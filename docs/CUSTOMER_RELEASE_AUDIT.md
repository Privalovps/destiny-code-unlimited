## Security changes

- Central local-environment predicate rejects production and known hosted/CI markers. Both the local checkout simulator and read-only preview use it. Existing loopback request checks remain in place for report preview.
- Public edition selection cannot be switched to a different sample using a deployed local rollback flag. Historical order selection remains separate and unchanged for live purchases.
- Existing authorizedOrder checks retain opaque UUID, session-token hash, server storage authorization, paid status, product ID, exact 1290 USD cents and environment validation.
- Private routes stay dynamic/private/no-store/noindex; `/result` also gets private headers to avoid public caching of dates. Metadata uses a valid HTTPS deployment origin, without production localhost fallback.
- Paid/sample PDF routes use Node.js, request a 60-second function limit, return generic private failures and cap buffered response size at 4,000,000 bytes. This limits returned payload size, not generator peak memory; real cloud timing/memory still requires verification. No files are stored locally or publicly.
- Node 24 and cloud install/build commands are explicit. A prebuild dependency-floor guard rejects the audited outdated Next 16.2.0. The approved Next 16.4.5 update must actually install before publication. The approved npm install failed with ENOTFOUND registry.npmjs.org; package and lockfile still resolve Next.js/eslint-config-next 16.2.0. Preflight correctly exits 1. No security patch is claimed installed.
- Ignore policies exclude secrets, build artifacts and private PDFs from Git/direct Vercel uploads.
